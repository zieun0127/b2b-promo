# 사장님 MBTI PRD (제품 요구사항 문서)

> 본 문서는 `docs/1-domain-definition.md` (v1.6)를 기반으로 작성되었다. 용어(엔티티명, 유스케이스 ID)는 도메인 정의서와 동일하게 사용한다.

## 1. 제품 개요 및 목표

### 문제 정의
외식사업자는 매장 운영 성향에 맞는 정보/조언을 얻기 어렵고, 운영자(플랫폼)는 참여 고객의 성향을 파악할 접점이 부족하다.

### 해결 방안
흥미 위주의 MBTI 테스트로 외식사업자(거래처)의 참여를 유도하고, 결과에 맞는 장사 TIP과 추천 프로모션을 제공한다. 관리자에게는 참여 현황/성향 통계를 제공한다.

### 비즈니스 목표
- 거래처 등록: 1,000개 이상
- 프로모션 기능(UC-1 결과 화면의 추천 프로모션 확인) 이용 건수: 3,000건 이상
  - **[확인 필요한 가정]** 등록 목표(1,000개 이상)보다 이용 목표(3,000개 이상)가 큰 이유는 원 요구사항(prd-prompt.txt)에 명시되어 있지 않음. 본 PRD에서는 "한 거래처가 재참여를 통해 여러 번 프로모션을 확인하는 것을 전제로 한 누적 이용 건수" 목표라고 잠정 해석함(도메인 정의서 재참여 규칙 참고). 실제 의도(고유 거래처 수 목표인지, 제출/조회 건수 누적 목표인지)는 사업 담당자 확인 후 8절 지표 정의를 확정할 것.

## 2. 범위

### 포함 (MVP, 도메인 정의서 2절 기준)
- 회원가입/로그인 후 서비스 이용
- MBTI 테스트(질문 응답 → 4개 지표 판정 → 16개 유형 중 1개 결과 산출, 규칙 기반)
- MBTI 유형별 설명, 장사 TIP 제공
- MBTI 유형별 추천 프로모션 정보 노출 (표시 전용, 쿠폰 발급/사용/결제 없음)
- **이벤트/프로모션 상시 목록 조회 + 관심 표시(북마크) + 인기 TOP3 + 신규/마감임박 뱃지** (v1.5)
- **관리자의 프로모션 등록/수정/삭제 및 MBTI 유형 매핑 관리** (v1.5)
- 계정별 테스트 참여 이력 저장 및 마이페이지에서 **참여 이력 전체 + 북마크한 프로모션** 조회 (v1.5, 기존 "최근 결과 1건"에서 확장)
- 관리자용 참여 현황 통계 (전체 참여자 수, 유형별/지표별 참여자 수·비율, **프로모션별 추천 매칭 수·북마크 수**)
- 반응형 웹 UI (모바일 테스트 참여, 데스크탑 관리자 통계 조회)

### 제외 (Out of Scope)
- 실제 상품 주문/결제, 쿠폰 발급, 포인트 적립
- 외부 쇼핑몰/POS 연동, 매출 데이터 자동 연동
- AI 기반 개인화 추천
- 네이티브 모바일 앱, 접근성(웹 접근성 표준 준수) 대응
- 프로모션 조회수/클릭 로그 추적 (인기도는 북마크 수로만 판단, v1.5)
- 프로모션 이미지 업로드, 알림(이메일/푸시) 발송 (v1.5)

## 3. 타겟 사용자 및 페르소나

| 액터 | 설명 |
|---|---|
| 외식사업자(회원, 거래처) | 회원가입/로그인 후 MBTI 테스트에 참여하고 결과/장사 TIP/추천 프로모션을 확인 |
| 관리자 | 참여 현황 및 성향 통계를 조회 |

상세 페르소나 시나리오는 본 PRD 범위에서 생략한다(교육용 MVP, 1인 개발 3일 일정 고려).

## 4. 핵심 기능 요구사항

### FR-1 (UC-1 기반): MBTI 테스트 참여 및 결과/장사 TIP/추천 프로모션 확인
- 로그인 사용자가 "MBTI 테스트 시작" 진입
- 지표당 3문항, 총 12문항 예/아니오 응답 (MbtiQuestion)
- 12문항 모두 응답 전 제출 버튼 비활성화 (예외 케이스 반영)
- 제출 시 E/I, S/N, T/F, J/P 판정 → 16개 유형 중 1개 결정 (MbtiResultType)
- TestSubmission 완료 상태로 저장, 결과 화면에 유형/설명/장사 TIP/추천 프로모션(PromotionOffer) 표시
- 마이페이지에서 최근 참여 이력 조회 (가장 최근 결과 기본 표시)
- 미로그인 사용자가 테스트 페이지 접근 시 로그인 화면으로 이동
- 로그인 성공 시 완료된 결과 유무로 목적지 분기: 완료 이력이 있으면 프로모션 목록(FR-3)으로, 없으면 테스트 화면으로 바로 이동 (v1.6)

### FR-2 (UC-2 기반): 관리자 참여 현황 및 성향 통계 조회
- 관리자 화면에서 전체 참여자 수(완료된 TestSubmission 기준) 집계 표시
- MBTI 유형별 참여자 수/비율 집계 표시
- E/I, S/N, T/F, J/P 지표별 참여자 비율 집계 표시
- 프로모션별 추천 매칭 수(매핑된 MBTI 유형 기준 완료 참여자 수) 및 북마크 수 집계 표시 (v1.5)
- 일반 사용자의 관리자 화면 접근 차단 (역할 기반 접근 제어)

### FR-3 (UC-3 기반): 이벤트/프로모션 목록 조회 및 관심 표시 (v1.5 신규)
- 로그인한 사용자가 "이벤트/프로모션" 화면에서 등록된 전체 PromotionOffer 목록 조회 (MBTI 검사 여부와 무관하게 접근 가능)
- 완료된 TestSubmission(최근 결과) 보유 시, 해당 유형에 매핑된 프로모션을 목록 상단에 추천으로 정렬
- 북마크 수 상위 3개를 "인기 프로모션"으로 별도 노출. 완료된 결과가 있으면 본인 유형에 매핑된 프로모션 내에서만 집계(없으면 전체 기준) (v1.7)
- 등록일/마감일 기준 "신규"/"마감임박" 뱃지 및 매핑된 MBTI 유형 뱃지 표시 (v1.7)
- "전체" 및 16개 MBTI 유형 버튼으로 목록 필터링, 완료된 결과가 있으면 자신의 유형이 기본 선택(없으면 "전체"). "인기 프로모션" 섹션은 이 필터 버튼 선택과는 무관하게 항상 본인 유형(또는 전체) 기준을 유지 (v1.6, v1.7)
- 프로모션별 관심 표시(북마크) 토글 — 마이페이지에서 북마크 목록으로 재조회 가능

### FR-4 (UC-4 기반): 관리자 프로모션 등록/수정/삭제
- 관리자 화면에서 프로모션(이름/설명/마감일/대상 MBTI 유형 1개 이상) 신규 등록
- 기존 프로모션 정보 및 MBTI 유형 매핑 수정
- 프로모션 삭제(연관된 Bookmark·유형 매핑도 함께 제거, 과거 TestSubmission 결과에는 영향 없음)
- 등록/수정/삭제 결과는 FR-1(추천 프로모션)과 FR-3(목록)에 즉시 반영
- 일반 사용자의 프로모션 관리 화면 접근 차단 (역할 기반 접근 제어)

## 5. 비기능 요구사항
- 반응형 웹 UI 필수 적용 (모바일/데스크탑 대응, 별도 모바일 앱 없음)
- 웹 접근성(스크린리더 등) 대응은 MVP에서 고려하지 않음
- 성능/부하 목표는 별도 정의하지 않음 (1인 개발, 3일 일정 특성상 과도한 최적화 지양)
- 인증: 이메일/비밀번호 기반 로그인, 역할(USER/ADMIN) 구분
- 인증 방식: JWT 기반, Access Token(짧은 만료)과 Refresh Token(긴 만료)을 함께 사용. Access Token 만료 시 Refresh Token으로 재발급. Refresh Token은 서버(DB)에 별도 저장하지 않고 stateless로 처리(만료로만 무효화, revoke 기능은 MVP 제외)

## 6. 기술 스택 및 아키텍처 제약
- 프론트엔드: React 19, 전역 상태관리 Zustand, TanStack Query로 백엔드 통신
- 백엔드: Node.js + Express, pg 라이브러리로 PostgreSQL 접근
- 데이터베이스: PostgreSQL 17
- 도메인 엔티티 ↔ DB 테이블: User, MbtiQuestion, MbtiResultType, PromotionOffer, TestSubmission, **Bookmark(v1.5 신규)** (도메인 정의서 4절 그대로 매핑)
  - 단, MbtiResultType-PromotionOffer는 N:N 관계이므로 관계형 DB 표현을 위한 조인 테이블(`mbti_result_type_promotion_offers`) 1개가 추가로 필요함 (`docs/8-erd.md` 참조)
  - User-PromotionOffer도 N:N 관계이며 `Bookmark` 엔티티 자체가 조인 테이블 역할을 겸함(v1.5, `docs/8-erd.md` 참조)

## 7. 일정 및 리소스
- 일정(초기 MVP): 3일, 1인 개발. FR-3/FR-4(v1.5 추가 기획)는 별도 일정으로 후속 진행.
- 우선순위: FR-1(테스트 참여 및 결과 확인) 우선 구현 → FR-2(관리자 통계) → 반응형 UI 다듬기 → **FR-3(프로모션 목록/북마크) → FR-4(관리자 프로모션 관리)** (v1.5)
- 예산: 1인 개발 인건비 수준 (별도 인프라/외부 서비스 비용 없음)

## 8. 성공 지표
- 거래처 등록 수(고유 User 수): 1,000개 이상
- 프로모션 기능(추천 프로모션 확인) 이용 수: 3,000개 이상
  - **[확인 필요]** 이 수치가 고유 거래처 수(`COUNT(DISTINCT user_id)`) 기준인지, 재참여 포함 누적 제출/확인 건수(`COUNT(submission)`) 기준인지 1절의 가정과 함께 확정 필요. 확정 전까지는 잠정적으로 후자(누적 건수 `COUNT(submission)`)로 간주함.
- 관리자 통계 화면에서 참여자 수/유형별 비율이 정상 집계되는지 여부 (기능 검증 지표)
- **재방문 지표(v1.5)**: 프로모션 북마크 수, 프로모션 목록 화면 재방문 빈도(월간 접속 사용자 수 기준). 조회수/클릭 로그를 쌓지 않으므로 정밀 리텐션 분석은 MVP 범위 밖이며, 북마크 수를 대리 지표(proxy)로 사용한다.
