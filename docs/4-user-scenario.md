# 사장님 MBTI 사용자 시나리오

> 참고 문서: [`docs/1-domain-definition.md`](./1-domain-definition.md) (도메인 정의서 v1.5), [`docs/2-usecase.md`](./2-usecase.md) (유스케이스 다이어그램), [`docs/3-PRD.md`](./3-PRD.md) (PRD)

본 문서는 PRD의 FR-1(UC-1 기반), FR-2(UC-2 기반) 및 비기능 요구사항(반응형 웹, JWT 인증)을 기반으로, 각 액터의 실제 사용 흐름을 골든 패스 중심으로 정리한다. 인구통계학적 페르소나 프로필은 다루지 않으며(PRD 3절 참조), 기능 사용 흐름만 다룬다.

---

## 시나리오 1. 신규 외식사업자 회원가입 → 로그인 → MBTI 테스트 참여 → 결과 확인 (골든 패스)

- **액터**: 외식사업자(회원)
- **사전 조건**: 서비스 최초 방문, 계정 없음
- **단계별 흐름**:
  1. 모바일 브라우저로 서비스 접속 → 랜딩 화면에서 "시작하기" 클릭
  2. 회원가입 화면에서 이메일/비밀번호 입력 후 가입 (User 생성, role=USER)
  3. 로그인 화면으로 이동, 방금 가입한 계정으로 로그인 → 서버가 JWT Access Token/Refresh Token 발급
  4. 로그인 성공 후 메인 화면 진입, "MBTI 테스트 시작" 버튼 클릭
  5. 테스트 화면에서 지표당 3문항씩 총 12문항(E/I, S/N, T/F, J/P)에 예/아니오로 순차 응답
  6. 12문항 모두 응답 완료 시 제출 버튼 활성화 → 제출
  7. 서버가 답변 조합으로 4개 지표를 판정하여 16개 유형 중 1개 결정, TestSubmission을 완료 상태로 저장
  8. 결과 화면으로 전환: 판정된 MBTI 유형, 유형 설명, 장사 TIP, 해당 유형에 매핑된 추천 프로모션(PromotionOffer) 표시
- **기대 결과**: 계정과 테스트 참여 이력(TestSubmission)이 생성되고, 결과 화면에서 유형/장사 TIP/추천 프로모션을 확인할 수 있다.

---

## 시나리오 2. 기존 회원의 마이페이지 최근 결과 조회

- **액터**: 외식사업자(회원, 과거 1회 이상 테스트 참여 이력 보유)
- **사전 조건**: 로그인 상태, TestSubmission(완료) 1건 이상 존재
- **단계별 흐름**:
  1. 메인 화면 또는 네비게이션에서 "마이페이지" 진입
  2. 시스템이 해당 계정의 TestSubmission 중 가장 최근 완료 건을 조회
  3. 마이페이지 화면에 최근 참여일시, MBTI 유형, 유형 설명, 장사 TIP, 추천 프로모션을 기본으로 표시
- **기대 결과**: 재로그인/재방문 시에도 별도 재참여 없이 가장 최근 결과를 즉시 확인할 수 있다.

---

## 시나리오 3. 동일 사용자의 재참여 (이력 누적, 최신 결과 표시)

- **액터**: 외식사업자(회원, 기존 참여 이력 보유)
- **사전 조건**: 로그인 상태, 과거 TestSubmission(완료) 1건 이상 존재
- **단계별 흐름**:
  1. 마이페이지 또는 메인 화면에서 "MBTI 테스트 다시 하기" 클릭
  2. 시나리오 1의 4~7단계와 동일하게 12문항 응답 후 제출
  3. 시스템이 기존 TestSubmission을 덮어쓰지 않고 새로운 TestSubmission을 이력으로 추가 저장
  4. 결과 화면에 새로 산출된 유형/장사 TIP/추천 프로모션 표시
  5. 이후 마이페이지 재진입 시, 방금 저장된 새 결과가 "가장 최근 결과"로 표시됨(기존 이력은 보존되나 기본 화면에는 노출되지 않음)
- **기대 결과**: 참여할 때마다 TestSubmission이 누적되고, 마이페이지 기본 화면은 항상 최신 참여 결과를 반영한다.

---

## 시나리오 4. 테스트 미완료 상태에서 제출 시도 (예외)

- **액터**: 외식사업자(회원)
- **사전 조건**: 로그인 상태, 테스트 진행 중, 12문항 중 일부 미응답
- **단계별 흐름**:
  1. 테스트 화면에서 일부 문항에만 응답 (예: 12문항 중 8문항 응답)
  2. 시스템이 미응답 문항 존재를 감지하여 제출 버튼을 비활성화 상태로 유지
  3. 사용자가 제출을 시도해도 버튼이 비활성화되어 있어 제출 요청 자체가 발생하지 않음
  4. 남은 문항에 모두 응답하면 제출 버튼이 활성화됨
- **기대 결과**: 미완료 상태에서는 TestSubmission이 생성되지 않으며, 관리자 통계(FR-2) 집계 대상에도 포함되지 않는다.

---

## 시나리오 5. 관리자의 참여 현황 및 성향 통계 조회

- **액터**: 관리자
- **사전 조건**: 관리자 계정으로 로그인 상태(role=ADMIN)
- **단계별 흐름**:
  1. 데스크탑 브라우저로 접속, 로그인 후 관리자 화면 진입
  2. 시스템이 완료된 TestSubmission 기준 전체 참여자 수를 집계하여 화면 상단에 표시
  3. MBTI 유형별(16개 유형) 참여자 수 및 비율을 차트/표로 표시
  4. E/I, S/N, T/F, J/P 각 지표별 참여자 비율을 함께 표시
- **기대 결과**: 관리자가 전체 참여 현황과 유형별/지표별 성향 분포를 한 화면에서 확인할 수 있다(미완료 제출은 집계에서 제외).

---

## 시나리오 6. 접근 제어 예외 (비로그인 접근, 일반 사용자의 관리자 화면 접근)

- **액터**: 비로그인 사용자, 외식사업자(회원, role=USER)
- **사전 조건**: 6-1은 로그인하지 않은 상태, 6-2는 일반 회원으로 로그인한 상태
- **단계별 흐름**:
  - **6-1. 비로그인 사용자의 테스트 페이지 접근**
    1. 로그인하지 않은 사용자가 URL로 테스트 페이지 직접 접근 시도
    2. 시스템(또는 클라이언트)이 JWT Access Token 부재/만료를 확인
    3. 로그인 화면으로 강제 이동
  - **6-2. 일반 사용자의 관리자 화면 접근 차단**
    1. role=USER 계정으로 로그인한 사용자가 관리자 화면 URL로 접근 시도
    2. 시스템이 역할(role) 기반 접근 제어를 통해 ADMIN 권한이 아님을 확인
    3. 접근을 차단하고 접근 불가 안내(또는 메인 화면 리다이렉트) 표시
- **기대 결과**: 미인증 사용자는 로그인 화면으로, 권한 없는 사용자는 관리자 화면에 진입하지 못하도록 차단되어 FR-1/FR-2의 접근 제어 요구사항이 충족된다.
